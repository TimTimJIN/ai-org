# AI自律基盤の案件管理

Windowsで `open_hub.cmd` を開きます。PythonとTkinterが必要です。起動できないときは、このフォルダーで `python hub_ui.py` を実行するとエラーを確認できます。

普段のClaudeで相談した場合は、依頼にしたい回答をClaudeの「コピー」でコピーし、Windows画面の「Claudeの回答を取り込む」を押します。先頭行から案件名を仮入力し、回答を依頼内容に入れます。実装担当の初期選択はClaude Codeで、画面で変更できます。内容を確認し、「作成して指示をコピー」を押せば開始指示も一度に作れます。クリップボードは取り込みボタンを押したときだけ読みます。JSONや専用の依頼文は不要です。

このPCのプロジェクトフォルダーを開いたCodexまたはClaude Codeで「Windowsに下書きを入れて」と頼むと、案件画面の「受け取った依頼」から開けます。内容と担当を確認して「この内容で作成」を押し、下書きを出した元の会話で「進めて」と伝えます。その会話が画面で選んだ実装担当なら、開始指示のコピー・貼り付けは不要です。別の会話や別の担当へ渡す場合は「作成して指示をコピー」を選びます。普通のWebチャットなど、この作業場所に書き込めない会話からはJSON読み込みを使います。画面で作成した時点ではAIの作業は始まりません。

1. 「案件を作る」から依頼を直接入力するか、ChatGPTやClaudeで作った案件JSONを読み込みます。画面で依頼と完成の目安を編集し、担当の組み合わせを選んで保存します。JSONの作り方は [チャットからの引き継ぎ](HANDOFF_FORMAT.md) を参照してください。
2. 実装担当への開始指示をコピーし、担当の会話へ貼り付けます。CodexやClaude Codeで作業場所の指定が必要なときは、画面に表示された案件フォルダーを選びます。
3. 途中成果物を成果物フォルダーで確認します。レビューを始めるときは、担当が作成したレビュー用コピーを選び、レビュー担当への開始指示を渡します。
4. 修正コメントは案件画面から保存します。担当が次の作業の区切りで読み、反映内容を記録します。停止と再開は下記の手順で管理します。

担当予定は「Codexが実装、Claude Codeがレビュー」と「Claude Codeが実装、Codexがレビュー」から選び、案件ごとに `ROLES.json` へ保存します。担当を交代するときは、前の担当が編集権を返したことを確かめ、次の担当で同じ作業場所を選びます。画面から変更した担当予定は、現在の編集権の保持者には影響しません。

「交互」にチェックを入れると（新しい案件の既定）、実装担当が作業を終えて編集権を返すたびに、基盤が実装とレビューを入れ替えます。例：Claude Code が実装して終える → 次は Codex が実装、Claude Code がレビュー → Codex が終える → 次は Claude Code が実装。入れ替えは Codex・Claude Code の共通の終了処理（finish・release）で行うので、どちらから操作しても同じです。レビューは実装担当が編集権を返す前に受けます。作業の途中で会話を終えるだけのときは `--keep-turn` を付けて番を保ちます。開いている案件画面は、入れ替わった担当予定を自動で表示します（未保存の選択があるときは上書きしません）。

案件ごとに `TASK.json` に依頼、`STATUS.md` に進捗・成果物の場所・次の作業、`outputs/` に成果物、`feedback/` にコメントを残します。新規案件の指示ファイルには、反映後に `workspace_hub.py acknowledge` を実行する手順があります。反映報告の担当名は自己申告です。成果物への反映は別途確認してください。

現在はローカルの案件準備と引き継ぎに対応しています。作業場所の選択、担当の切り替え、画面の再読込は手動です。自動起動、常駐処理、即時通知は未実装です。通常のチャットや別端末からの利用には、案件フォルダーにアクセスできる作業環境が必要です。

## CodexとClaude Codeで実装とレビューを並行する

作業の役割は交代できます。編集担当は案件フォルダーで編集権を取得し、レビュー担当は指定された版のコピーを別のフォルダーで開きます。新規案件の指示ファイルにはこの手順が含まれています。旧版で作成済みの案件にもコマンドは使えます。その場合は担当にこのガイドも読ませてください。

1. 編集担当がコマンドを実行して、返されたトークンを作業中に保持します。すでに担当がいる場合は取得に失敗します。画面の「進捗・成果物」を再読込すると保持者を確認できます。
   ```powershell
   python ../../workspace_hub.py claim --case $caseId --agent "Codex セッション名"
   ```
2. 編集担当は書き込みと書き込みを伴うテストを一時停止し、共有してよいファイルを明示してレビュー用ZIPを生成します。コピーが完成したら、元の案件で修正を再開できます。認証情報や顧客データが含まれていないことを確認します。コマンドはZIPのパスを返します。
   ```powershell
   python ../../workspace_hub.py snapshot --case $caseId --token $editToken outputs/spec.md outputs/example.py
   ```
3. レビュー担当は別フォルダーに展開したコピーを読み、ZIPのファイル名から拡張子を除いたレビューIDとともに結果を残します。報告コマンドは案件フォルダーで実行します。報告は `reviews/<レビューID>-<報告ID>.json` へ追記されます。保存時に現行ファイルとの差異や読取不可を確認し、該当件数を表示して記録します。指摘を反映する前に、編集担当が現行版にも当てはまるか確認します。
   ```powershell
   python ../../workspace_hub.py review-note --case $caseId --review $reviewId --agent "Claude Code" --note "確認結果"
   ```
4. 編集の終了または担当交代時に編集権を返します。次の担当は新しい編集権を取得します。
   ```powershell
   python ../../workspace_hub.py release --case $caseId --token $editToken
   ```

`$caseId` は `TASK.json` のID、`$editToken` は取得時に返った値です。編集権はWindowsのロックを使って同時取得を拒みます。アプリやエディターからの直接編集には、各担当が取得手順を守る必要があります。

担当が異常終了した場合も編集権は自動失効しません。前の担当と関連プロセスが停止し、書き込みがないことを人が確認してから、「進捗・成果物」に表示される編集権IDを指定して復旧します。復旧者と理由が記録されます。

```powershell
python ../../workspace_hub.py recover --case $caseId --claim $claimId --agent "復旧者名" --reason "旧セッションと書込みプロセスの終了を確認" --confirmed-stopped
```

## 途中成果物を見て止める・方針を変える

1. 案件の「進捗・成果物」と `outputs/` を確認します。作業中のファイルを固定した版で見たい場合は、編集担当が作ったレビュー用コピーを開きます。
2. 「一時停止を要求」を押します。編集担当がいる場合は「停止要求中」と表示されます。担当は `work-state` を着手前と作業の区切りで読み、停止要求があれば書き込みを止め、途中成果物と未完了事項を示してから `pause-ack` を実行します。「停止報告あり」は編集担当の申告です。編集権の保持者がいない場合はその状態を表示し、新たな編集権の取得は再開まで拒否されます。
3. 「方針を確認して再開」を押し、変えたい方針を書いて保存します。空欄なら直前の方針を引き継ぎます。再開後の担当は `work-state` の `direction` と、依頼・修正コメントを読みます。編集担当が `confirm-direction` で報告すると、画面が「担当が方針を確認済み」に切り替わります。担当を替えた場合も確認が必要です。

```powershell
python ../../workspace_hub.py work-state --case $caseId
python ../../workspace_hub.py pause-ack --case $caseId --request $requestId --token $editToken
python ../../workspace_hub.py confirm-direction --case $caseId --request $requestId --token $editToken
```

`$requestId` は `work-state` に表示される停止要求IDです。保存先は案件内の `.editing/work-control.json` です。停止報告を待っている間に担当が異常終了した場合は、上記の `recover` 手順で停止を確認し、編集権を復旧できます。急ぐときは作業中のアプリでも停止してください。案件画面はAIへの即時通知、強制停止、自動起動に対応していません。レビュー担当も区切りで状態を確認しますが、画面の停止報告と方針の確認報告は編集担当分です。会話が終了していれば、再開を保存した後に案件フォルダーを開き直して担当に作業を依頼します。旧版の案件では担当にこのガイドを読ませてください。
