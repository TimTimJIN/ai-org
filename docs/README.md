# Chat Relay — 模擬検証版

既存のChatGPT・Claude会話を中継するWindows用試作です。**独立プログラムによる実アプリの自動往復は未完成です。** 追加のモデルAPI呼び出しはありません。

## 起動

WindowsとPython（tkinterを含む）が必要です。`start.cmd`を開くか、このフォルダーで`python app.py`を実行します。

1. 「模擬テスト」を選択する。
2. テーマと往復数（1〜5）を設定する。
3. 「接続確認」→「開始」。2往復なら各担当の模擬回答が2回表示されます。
4. 「中継を停止」で次の送信を停止します。送信済み内容や相手の生成は取り消しません。

模擬回答は固定文で、実モデルの回答ではありません。実アプリ接続は読取確認だけで、送信はGUI・Python・PowerShellの入口で無効です。読取確認も実環境での成功は未検証です。実アプリを使う場合の画面情報の鮮度、チャットの一意識別、回答完了の検出を改善する必要があります。

## ログ・異常終了

ログは`data/logs/*.jsonl`。`CHAT_RELAY_DATA`で保存先を変更できます。平文の回答を含むため、他人と共有するフォルダーは指定しないでください。

異常終了後に`data/RUNNING.lock`が残る場合は、自動復旧しません。まずタスクマネージャーでこのアプリのプロセスが終了したことを確認し、最後のログと対象会話を照合してください。送信意図だけがある場合、未送信とは断定できません。確認後にロックを別名へ変更して、新規実行として開始します。旧セッションの送信を自動再送する機能はありません。

前版が作成したログは`%LOCALAPPDATA%/ChatRelayPrototype`に残る場合があります。本版はそこを変更しません。

## 検証

`python -m unittest discover -s . -v`

15件合格：回数制限、下書き保護、送信先変更、重複、別発言の割込み、送信結果不明時の再送禁止、停止、空白を含む内容照合、完了証拠の必須化、過長回答の遮断、実送信禁止。

UI/UX・実装担当：Codex。実アプリのコード全文レビューとE2Eは未完了。設計レビューの経緯と残課題は`REVIEW.md`参照。

## 次の開発条件

- ChatGPTのチャット名だけに頼らず、URL等の不変IDで対象を識別する。
- 送信直前に画面・入力欄・会話を新たに取得し、古い情報なら停止する。
- 完了を示すUIを個々の回答に紐づける。6秒安定だけでは完了にしない。
- 前面表示・手動操作・通信断・クラッシュを含む実機試験を行う。
- ClaudeとGeminiへコードと検証証跡を渡し、重大指摘を解消して再確認する。

現在の配布物は模擬検証用であり、常駐運用や無人の連続運転には使用できません。
