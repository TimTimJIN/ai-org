# チャットで作る案件JSONの形式

普段のClaudeで相談した回答なら、回答をコピーし、Windows画面の「Claudeの回答を取り込む」を押せば下書きにできます。この経路では、専用形式のJSONを作る必要はありません。以下はファイルで渡したい場合の手順です。

このPCに接続したCodexやClaude Codeであれば「Windowsに下書きを入れて」と頼み、案件画面の「受け取った依頼」から開けます。作業場所に書き込めないチャットから引き継ぐときは、以下のファイル読み込みを使います。

案件ワークスペース（`python workspace_hub.py`）の「＋ 案件を作る」→「チャットで作ったJSONを読み込む…」で読み込むファイルの形式です。
読み込んだ内容は **下書き** として入力欄に入るだけです。内容と担当予定を確認・編集し、「作業場所を作成」を押したときに初めて案件が作られます。
読み込み・作成のどちらでも、外部への送信やAIの起動は行いません。

## 形式

- 文字コード: **UTF-8**（BOM付きも可）。ファイルサイズは **200KB以内**。
- 最上位は1つのオブジェクト `{ ... }`。使える項目は次の3つだけです（それ以外の項目があると読み込みを中止します）。

| 項目 | 必須 | 型 | 上限 | 内容 |
| --- | --- | --- | --- | --- |
| `title` | 必須 | 文字列 | 1〜100文字、改行不可 | 案件名 |
| `objective` | 必須 | 文字列 | 1〜12,000文字 | 依頼内容 |
| `acceptance` | 任意 | 文字列 | 12,000文字以内 | 完成の目安（受け入れ条件） |

- 前後の空白は取り除いてから文字数を数えます。
- 本文の改行は `\n` で書きます。タブ・改行以外の制御文字、UTF-8で保存できない文字（孤立したサロゲート `\ud800` など）、`NaN`/`Infinity`、同じ項目の重複、深い入れ子は読み込みエラーになります。
- 実装担当・レビュー担当（Codex／Claude Code）はJSONに書きません。画面で選びます。`role` などの項目を足すと未対応の項目としてエラーになります。

## 例

```json
{
  "title": "営業向け提案資料の作成",
  "objective": "新サービスの提案資料を作る。\n対象は既存顧客の情報システム部門。",
  "acceptance": "日本語でA4横8枚以内。\n価格表と導入スケジュールを含める。"
}
```

完成の目安を省略する場合:

```json
{"title": "議事録テンプレートの整理", "objective": "社内会議用の議事録テンプレートを1つにまとめる。"}
```

## チャットへの依頼文の例

ChatGPTまたはClaudeに依頼を相談したあと、次のように頼みます。

```text
ここまでの依頼を、Windowsの案件ワークスペースに読み込む
UTF-8のJSONファイルにして、ダウンロードできるようにしてください。
- キーは title, objective, acceptance の3つだけ（他のキーは入れない）
- title は100文字以内で改行なし、objective と acceptance は各12,000文字以内
- ファイル名は case-draft.json にする
```

ダウンロードしたファイルをWindows画面で選びます。ファイルを作れない会話では、JSON本文をUTF-8の `.json` として保存して読み込みます。

## 読み込み後の流れ

1. 下書きの案件名・依頼内容・完成の目安を確認し、必要なら直接編集する。
2. 担当予定（「実装 Codex → レビュー Claude Code」または「実装 Claude Code → レビュー Codex」）を選ぶ。「交互」（既定でオン）のままなら、実装担当が実装とレビューを終えるたびに実装とレビューが入れ替わります。
3. 「作業場所を作成」で確定する。担当予定は `ROLES.json` に保存され、案件上部からいつでも変更できます。

担当予定は「誰に頼む予定か」の記録で、編集権（`claim` で取得する排他）とは別です。担当予定を変えても、現在の編集権の保持者は変わりません。
